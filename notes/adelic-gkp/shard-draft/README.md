## Why the reviewed statements are `sketched` and not `proved`

All four REFUTE reviews (`notes/reviews/adelic-gkp-{lattice,arithmetic,zeta,ff-family}-2026-10-06.md`) are by `claude:opus-5.5`. That is the
same model that wrote the lane pages. The gate refuses `proved` when `reviewer=` equals the author (`labbook_check.py`: "reviewer equals author"), and
HANDOFF item 8 states the convention ("`proved` requires a reviewer ≠ author"). So I followed the precedent of `prop:toric-filtration-not-frobenius`
(sketched, with "restore status after review"). Each of the 13 rows already carries a `review-alias=<label>` that names a VALID verdict in its review file,
and the note says "same-model REFUTE review … promote to proved after a review by another model". The ff-family review existed when the rows were written,
so lanes J and M carry its verdicts (J1–J6, J9–J11, J13 VALID; J7, J8, J12 MINOR applied; M1–M4 VALID), not "review pending".

Promotion test (second scratch copy, `…/laneP/promoted/`). I flipped the 13 rows to `proved`, added `reviewer=claude:opus-5.5`, and updated the shard's
`\claimstatus`. The gate then reports exactly 13 new errors, all `<id>: reviewer equals author`. No alias was rejected. So after a review by another model,
promotion needs only three changes per row: the status, the `reviewer=` field, and the review file (or a `VERDICT <id>: VALID` line in it).

"Checked only" has no gate status (`CLAIM_STATUSES` has no `checked`). Checked-only results are therefore `numerical` rows with kind `numerical`. Each
cites its check script as proof and the check's output in the note.

## How to register (one move)

```sh
sh notes/adelic-gkp/shard-draft/register.sh      # from the repository root
```

The script does the following:

1. Copies the shard to `report/sections/04za_adelic_gkp_ladder.tex`.
2. Inserts `\include{report/sections/04za_adelic_gkp_ladder}` right after the `04z_cerednik_drinfeld` line of `report.tex`. The gate requires the include
   order to equal the sorted file names, and `04za…` sorts between `04z_…` and `05_…`.
3. Appends the three TSVs, without their headers, to `db/claims.tsv`, `db/definitions.tsv` and `db/provenance.tsv`.
4. Copies the twelve check outputs `notes/adelic-gkp/checks/output_<x>.txt` to `outputs/check_<x>.txt`; see the SHARD-SCRIPTS rule below.
5. Runs `python3 scripts/labbook_check.py --regen` (`make regen`), then `python3 scripts/labbook_check.py` (`make check`).

### What `make check` demands, and how the draft meets it

- **SHARD-ID.** The gate reads `% SHARD-ID:`, not `SHARD-LABEL`, and its regex `^RC-\d{2}[A-Z]?-…` allows one letter only, so `RC-04ZA-…` is rejected.
  The draft uses `RC-04Z-ADELIC-GKP-LADDER`. Shards 04q already share a letter (`RC-04Q-DENINGER-CMPS`, `RC-04Q-H-THETA-REFUTED`).
- **Header lines.** The shard has 3 SUMMARY lines, KEYWORDS and TITLE. README and SHARD_CATALOG are regenerated by `--regen`.
- **Notes parity.** It covers **top-level** `notes/*.md` only. A SHARD-NOTES entry that is not top-level is an error ("not a top-level note"), so
  `notes/adelic-gkp/*.md` cannot be listed there and need no parity row. The draft has `% SHARD-NOTES: none`, as 04u and 04w do for their sub-directory
  pages. The distilled pages are named in a non-gate comment `% DISTILLED-PAGES:` and in the prose.
- **SHARD-SCRIPTS parity.** Every listed file must exist, and `outputs/<stem>*.txt` must exist for it. The twelve `check_*.py` exist under
  `notes/adelic-gkp/checks/`, but their outputs are `checks/output_*.txt`. Step 4 therefore copies them to `outputs/check_*.txt`; symlinks also satisfy
  the gate. This is the one write outside `report/`, `db/` and `report.tex`. No other shard is touched.
- **Claims.**
  - Every environment has exactly one `\label` and one `\claimstatus` equal to the derived status.
  - Kinds match: `\begin{theorem}` with a `cit:` label is allowed for a citedfact, as in 03e.
  - Each cited environment reproduces its provenance quote inside `\texttt{\detokenize{…}}`.
- **Provenance.**
  - The quotes must be found in `refs/src/1501.02446/AVFp_final_.tex` and `refs/src/1304.4132/IF1.tex`.
  - Both files are on disk in this container, but `refs/src/` is git-ignored, and neither id is in `refs/fetch_sources.sh`. They are listed only in
    `refs/manifest-2026-10-06-pending.txt`.
  - **In a fresh clone the gate will report three more "not present" errors** until the owner merges that manifest into `fetch_sources.sh`. The
    registration does not need any other shard to change.
- **Notation.**
  - No `\newcommand`. Only macros from `db/notation.tsv` are used (`\Tr`, `\re`, `\im`, `\Fq`, `\Fp`, `\zero`, `\hol`), plus standard LaTeX.
  - Bare Greek letters that the table reserves for other meanings (`\Omega` is `\Cas`, `\psi` is `\cheb`, `\Lambda` is `\vM`, …) are marked
    `% bare-ok`, as 04u and 04w do. The warning count is unchanged.
  - Wanted macros are listed in the `% WANTED MACROS` comment: field trace, $W_\Omega$, $G_J$, $\Phi_+$, $\Omega_{\rm FE}$.
- **Lines.**
  - The gate allows at most 320 lines per shard.
  - To fit, the draft wraps prose at about 178 characters (other shards use about 130). It also puts `\label` and `\claimstatus` on one line and has no
    blank line between consecutive environments.
  - If the owner prefers the usual layout, split the arithmetic part (lanes C, I, J: `prop:gkp-cm-local-not-global`,
    `prop:gkp-gate-phases-root-number`, `prop:gkp-ff-dirichlet-rung`) into a second shard `04zb_…`, as `registered-record.md` §8.3 suggests. Each
    shard would then need its own SHARD-ID with a free suffix, e.g. `RC-04Z-ADELIC-GKP-PHASES`.
